# AgentGDB usability and readiness audit

**Review date:** 2026-11-02
**Revision reviewed:** local working tree on `codex/agentgdb-usability-safety-fixes`, HEAD `e413c60`, plus uncommitted project-registry, watcher-lifecycle, and Windows launcher messaging changes; not published.
**Method:** Source/documentation review, local automated tests, one disposable Codex CLI 0.166.0 model-driven mediation run, and a disposable macOS browser setup check; no real developer panel or independent security review was conducted.

## Opinion

AgentGDB targets a real problem, but it is not production ready. Its narrow product job is local coding-agent session inspection plus explicitly supervised MCP file and exact-command actions. This working tree adds a synthetic first-run demo, transcript parse feedback, a narrow proxy-side tool-call gate, an official MCP stdio adapter that executes its own read/write/command tools after policy and approval checks, captured single-turn playback, credential-pattern redaction, and a cross-platform CI definition. The managed adapter only mediates its own tools; clients must disable alternate native tools, and the path checks are not an OS sandbox. Local tests are evidence for these specific paths, not readiness certification.

## Changes made

1. New installs have an empty project registry and no guessed transcript or project paths.
2. Server binds to `127.0.0.1` by default; non-loopback binding requires a bearer token checked on API, static, and WebSocket requests. Wildcard CORS was removed.
3. Drift status is `UNKNOWN` when unavailable. MCP scope checks remain advisory. The OpenAI-compatible proxy checks a narrow supported tool-call subset and denies unknown formats, paths, and symlink escapes before returning calls. Mutating approvals include the workspace and policy fingerprint; policy is reloaded and checked again after approval before the call is released to the client. An integration regression verifies a policy change during the pending approval withholds the call. The filesystem check is still snapshot-based and is not OS enforcement.
4. VFS rejects root escapes and symlinked external ancestors, validates all paths before commit, stages replacement writes, and uses rename for per-file replacement. Multi-file atomicity is not promised.
5. Payload capture remains opt-in; common credential patterns are redacted before persistence. Captured turns include schema/engine versions and hashes; incomplete or mismatched traces fail replay explicitly. Fixture playback is verified after daemon restart and reports zero upstream calls; this is stored-turn playback, not agent re-execution.
6. Mutating tool calls wait on a durable approval record. Both approval-detail reads and decisions require the operator token, and approval responses disable caching. Timeout and server restart close the proposal without returning it to the client. Integration assertions verify unauthenticated reads are rejected and confirm the stored write target/content and executable/argument list shown for approval.
7. Dashboard workspace/transcript setup, synthetic demo, an end-to-end official MCP stdio test, prior Claude Code CLI MCP discovery, auth tests for HTTP/static/WebSocket, hostile-transcript rendering checks, trace-deletion integration tests, and a Node 22/24/26 Linux/macOS/Windows CI matrix with npm audit are configured. A disposable browser run verified the dashboard and a valid transcript setup. Codex CLI 0.166.0 completed a bounded read, approved write, approved exact command, denied non-allowlisted command, approval timeout, service-loss denial, daemon-restart rejection, and caller-cancellation denial through AgentGDB with native shell disabled; see the [run record](REAL_AGENT_RUN_2026-11-02.md). Dashboard CSS/fonts are bundled locally. Trace purging is transactional and can remove old session summaries when no newer turns remain. Remote matrix and cross-platform validation remain unverified; the host run is not tied to a release commit.
8. Project registry writes use a unique same-directory temporary file, flush it, and rename it into place. Registry startup now refuses a symlinked state directory or a symlinked/multiply linked config file; POSIX regression tests verify external targets are not read or replaced. Legacy default cleanup uses product-owned path patterns; developer-specific absolute paths and transcript identifiers were removed from source. Migration tests confirm unrelated projects with reused IDs are retained. This does not serialize concurrent writers or remove same-user TOCTOU races, and Windows ACL behavior remains unverified.
9. Project switching validates configured transcript availability and starts a candidate watcher before committing active-project state and stopping the previous watcher. Integration tests cover transcript-to-workspace-only transitions and an injected candidate startup failure that preserves the selected project and previous observer. Cross-platform behavior remains unverified, and observation is advisory.
10. Gemini CLI 0.25.2 connected to AgentGDB with a test configuration that allowlisted the AgentGDB MCP tools and disabled built-in tools. A bounded task did not reach the model because Gemini reported that no auth method or credential was configured. This verifies MCP discovery only.
11. The first-run dashboard now uses labeled responsive fields to register and activate a workspace, derives a unique editable URL-safe ID from its name, requires a non-empty relative path allowlist, and accepts an optional transcript path in the same form. Dashboard registrations use create-only semantics; the server refuses an ID collision so existing workspace settings are not silently replaced. Transcript paths must resolve to files; activation rejects malformed-only or unsupported-only JSONL before changing the active workspace, reports skipped malformed lines, and emits recognized existing events to the dashboard. Workspace, activation, and demo network errors are surfaced in the setup status. Unit tests cover ID normalization and collisions; local integration tests verify create-only refusal leaves the existing workspace unchanged. Clean Linux and Windows browser runs remain outstanding.
12. Codex CLI 0.166.0 had earlier MCP dispatch attempts blocked by the host's noninteractive `never` policy, including configurations using AgentGDB server/tool approval mode `auto`. A later bounded run succeeded after configuring `approve` for only the temporary AgentGDB MCP server and its allowlisted tools, while keeping the native shell disabled and AgentGDB's own authenticated approval gate active. Host runs verified a mediated read, operator-approved write, operator-approved exact command, non-allowlisted command denial, approval timeout, denial on service loss, daemon restart rejection, and caller cancellation in disposable workspaces. These results are from an uncommitted macOS candidate, not release-commit evidence. See the [run record](REAL_AGENT_RUN_2026-11-02.md). Do not use global approval/sandbox bypasses.

13. The current candidate requires the per-run operator token for loopback `/api/*` routes except the in-memory demo, validates browser request origins, and binds managed and proxy approvals to the action, workspace, and a versioned policy fingerprint. Both execution paths recheck policy before action release/execution. Before either path creates an approval, it now denies if redaction would alter the complete action-plus-policy context; integration regressions confirm the managed path writes no file and the proxy returns no mutating tool call. Managed command approvals also show the resolved executable path and SHA-256, revalidate identity before execution, and deny a changed binary. Field-aware redaction now handles nested authorization, API-key, cookie, credential, password, and private-key values; common Authorization/Cookie headers and Bearer/Basic scheme values are masked in text. Approval action details, decision reasons, and execution summaries are redacted at the database boundary. This remains heuristic and cannot guarantee detection of every secret format. Windows `.bat` and `.cmd` command launchers now fail with a specific explanation and a direct-executable workaround; the Windows-only test is skipped on macOS. Replay responses explicitly identify stored-turn playback and state that no agent was re-executed. Transcript input is capped by `AGENTGDB_MAX_TRANSCRIPT_BYTES` (64 MiB default); the live watcher consumes appended bytes and stops with a visible error at the cap. The npm package has an explicit allowlist; a dry run reports 31 runtime/README files and the packaging regression excludes tests, workflows, and evaluation materials. An isolated Node 22.23.4 install verified CLI help, daemon health, dashboard, and demo startup from the packed artifact; a packaged MCP stdio client read an allowlisted disposable fixture. These do not establish a model-driven package run. The release validator requires package license metadata and a repository `LICENSE` file, and rejects a LICENSE symlink outside the repository. The owner subsequently selected MIT; package metadata and the LICENSE file were added on 2026-11-02. This selection does not substitute for independent legal review. Fresh current-source copies pass `npm ci`, audit, CSS build, and the 90-test suite (89 passed, one Windows-only test skipped) under Node 22.23.4, 24.22.2, and 26.13.0 on macOS ARM64. Linux/Windows runtime checks, hosted CI, independent security review, and observed pilot remain outstanding. This candidate remains uncommitted and is not release-ready.

## Remaining limitations

- Proxy checks can be bypassed by any client configured to another endpoint. No independent tool runtime or OS sandbox exists; symlink validation is a race-prone snapshot check.
- Tool schema support is intentionally narrow. Named real coding-agent clients, cancellation under real host shutdown, browser accessibility, clean OS installs, and upstream timeout behavior still need validation.
- Remote auth is a basic shared bearer-token check, not a full account/session system. The dashboard browser cannot set auth headers by itself in remote mode; use a trusted local reverse proxy/client setup. Do not expose publicly without further review.
- Metadata such as session ID, model, token count, and latency is still persisted even when payload capture is disabled.
- Trace deletion removes rows transactionally and reports whether WAL checkpointing completed. If a reader pins the WAL, the caller must close it and retry; the API does not claim storage checkpoint completion in that case. Deletion cannot erase filesystem snapshots, copied databases, or backups.
- The approval token is a local friction barrier, not protection from a hostile process running with the same OS-user access.
- Credential redaction is pattern based and can miss novel secret formats. It is not a data-loss-prevention guarantee.
- The first-run form requires manually entering absolute local paths; it does not provide a native file picker. Transcript parsing supports only recognized schemas, and transcript observation remains advisory.
- VFS file replacements are staged per file, but a failure across multiple files may still leave a partial multi-file commit.
- No 1,000-person survey or observed pilot has been run. The facilitator and response form is ready at [DEVELOPER_PILOT_FORM.md](DEVELOPER_PILOT_FORM.md). Any simulated agent personas must be reported as synthetic review, not developer opinions. Run the observed 8–12 person formative pilot before considering a larger survey.

## Real-user study plan

Recruit 8–12 developers who actively use long-running coding agents. On a clean machine, ask each to install/start, connect a fixture transcript, interpret an event, distinguish alerting from blocking, find/delete stored data, and recover from a missing transcript. With consent, record completion, time, errors, help required, and comprehension of safety limits. Publish the instrument and anonymized results. Consider a larger survey only after this pilot demonstrates a usable product and a meaningful target population is defined.

## Follow-up implementation note

The managed MCP command path now routes through a bounded process runner. Timeout, caller cancellation, and output overflow initiate process-tree termination; inability to confirm Windows termination is surfaced as a failed command. Unit tests cover timeout and caller-cancellation descendants, and an integration test covers a timed-out descendant through the official MCP adapter. This remains best-effort lifecycle management, not a sandbox: POSIX descendants may detach into a new session, Windows behavior needs hosted Windows execution, and a hostile same-user process remains outside the boundary. These local tests do not close the broader release gates listed above.
