# Feature status and limitations

Status reflects a source-level review as of 2026-11-02, not independent certification.

| Capability previously advertised | Current status | Limitation |
|---|---|---|
| Local web dashboard and WebSocket | Implemented, minimally | First-run flow offers a privacy-safe demo without credentials and workspace setup after operator authentication. Without a token it gives neutral setup guidance and does not call protected workspace/activity APIs. The form validates an attached transcript before registration, registers and activates a workspace, derives an editable unique ID from its name, and uses create-only registration; malformed-only or unsupported transcripts fail before the ID is consumed. Connection and parse errors are surfaced. WebSocket state is visible and reconnects with capped exponential backoff. The in-memory demo returns its fixture over HTTP and performs no project write, upstream call, or trace persistence. Narrow screens use a stacked timeline/inspector layout; rendered narrow-screen review found and fixed inspector text clipping, with broader multi-viewport visual and accessibility review still outstanding. Transcript reads are capped by `AGENTGDB_MAX_TRANSCRIPT_BYTES` (64 MiB default); live watching stops with a visible error at the cap. |
| Browser-origin request check | Implemented, narrowly | Requests with an `Origin` header must match the daemon origin; loopback mode also requires a loopback hostname, reducing browser CSRF and DNS-rebinding exposure. Requests without `Origin` remain possible for CLI/MCP clients, so this is not local-process authentication. |
| Loopback API and live-event operator token | Implemented, narrowly | Loopback `/api/*` routes require the per-run operator token, except the in-memory synthetic demo. Loopback WebSocket clients must authenticate before receiving session or approval events; inbound frames are capped at 4 KiB. This protects against unauthenticated local clients but does not protect against a same-user hostile process or token theft. The OpenAI-compatible `/v1` endpoint remains separate. |
| Project registry | Implemented, local | New installs start empty; updates use a flushed temporary file and rename. The registry refuses a symlinked state directory and symlinked or multiply linked config file before reading/writing; regression tests verify outside targets remain untouched. Legacy seeded-path migration uses product-owned path patterns without embedding developer-specific absolute paths. Project-switch integration coverage verifies candidate observer startup failure preserves the active project and prior observer. Concurrent writers and same-user TOCTOU races are not eliminated, and Windows ACL behavior still needs platform validation. |
| OpenAI-compatible chat completion proxy | Implemented, minimally | No demonstrated Anthropic/Ollama compatibility or production reliability. |
| Transcript monitoring | Best effort | Observes files after writes; does not control agent execution. Project switches validate and start the candidate watcher before promoting it and stopping the previous watcher; selected transcript must exist and be a file. |
| Active goal extraction | Partial | Depends on specific transcript schemas and may not find goals. |
| Scope drift alerts | Advisory | Transcript drift alerts remain observational. |
| Proxy tool-call gate | Implemented, narrowly | Runs before supported OpenAI-style tool calls are returned, including buffered streams. Mutating approvals persist the selected workspace and policy fingerprint; after approval, the proxy reloads policy and revalidates before returning the call. Unknown schemas/paths, Windows drive-prefixed paths (including drive-relative forms), UNC paths, reserved Windows device names, alternate data stream syntax, invalid Windows characters, trailing-dot/space aliases, and any symlink component deny. Windows path policy comparison is case-insensitive; unit coverage simulates Windows, but platform runtime validation is outstanding. Checks remain snapshot-based and race-prone; not OS enforcement; a client can bypass the proxy. |
| Managed MCP tool adapter | Implemented, narrowly | Official stdio server exposes read, write, and exact argv command tools. Scope patterns accept exact relative paths (one normalized path only), `<directory>/**`, and explicit `**`; ambiguous wildcards are rejected during registration, and invalid stored policies return `UNKNOWN`/deny. Existing configurations using unsupported wildcard forms must be corrected before actions will run; directory access requires an explicit recursive rule. Command approvals display the resolved executable path and SHA-256; the adapter rechecks identity and executes by resolved path, denying a changed binary before execution. Executable identity checks use the bounded `AGENTGDB_MAX_COMMAND_EXECUTABLE_BYTES` setting (512 MiB default) and do not eliminate same-user filesystem races. On Windows, `.bat` and `.cmd` launchers (including `npm.cmd`) are denied because safe shell-free launch is unsupported; use a direct executable such as Node with a CLI entry point. This message is tested with a Windows-only regression test, but Windows runtime validation remains outstanding. Codex CLI 0.166.0 completed an authenticated bounded read, operator-approved write, operator-approved exact command, denied non-allowlisted command, timeout, approval-service-loss denial, daemon-restart rejection, and caller-cancellation denial in disposable workspaces with native shell disabled. See the [run record](evaluation/REAL_AGENT_RUN_2026-11-02.md). Evidence is for one uncommitted macOS candidate, not a release commit; Claude Code/Gemini remain discovery-only. Known-secret redaction is heuristic. Agents must disable alternate native tools to keep actions on this path. |
| MCP scope check helper | Advisory | Requires an active watcher; reports `UNKNOWN`/denies when unavailable. It is diagnostic, not the managed tool adapter. |
| Trace payload capture | Opt-in, redacted heuristically | `AGENTGDB_TRACE_CAPTURE=true`; common token patterns, structured authorization/API-key/cookie/secret/password/private-key fields, and common Authorization/Cookie headers are redacted. Unknown secret formats can remain; this is not data-loss prevention. Metadata is stored regardless. Age-based purge removes turns and approval records. |
| Trace retention | Optional | `AGENTGDB_TRACE_RETENTION_DAYS=1..3650` purges expired turns, approvals, and sessions at startup; unset disables automatic cleanup. Startup emits per-table removal counts and the configured window. Pending approvals interrupted by restart are rejected and counted in the same startup log. |
| Trace deletion and local storage | Implemented, local | The dashboard exposes authenticated, confirmed, date-based deletion for older turns and approvals; an optional control also removes old session summaries with no remaining turns. The API transactionally deletes and reports whether WAL checkpointing completed; if a reader pins the WAL, it reports incomplete and the idempotent operation can be retried after readers close. SQLite secure-delete is enabled. On Unix, the state directory/database are restricted before SQLite opens; symlinked state directories/database files are refused. Windows ACL behavior remains unverified, and filesystem snapshots/backups are outside the deletion boundary. |
| Human approval | Implemented, narrowly | Durable SQLite queue; both approval-detail reads and decisions require the operator token, and responses disable caching. Managed writes/commands wait for explicit decisions bound to a displayed action, workspace, versioned policy snapshot, and fingerprint; policy changes before execution deny. Proxy calls also wait for explicit decisions. Before either path creates a pending record, it denies if redaction would alter the complete action-plus-policy context, preventing the stored/displayed approval from differing from the action context used for execution. Timeout, cancellation, unavailable dashboard, and daemon restart deny. Approval action details, decision reasons, and execution summaries are redacted again at the database boundary. Same-user hostile process and filesystem races remain outside this guarantee. |
| Managed command timeout / subprocess halt | Implemented, narrowly | Managed MCP commands route through a bounded runner that requests POSIX process-group or Windows `taskkill /T /F` termination on timeout, caller cancellation, or output overflow; inability to confirm Windows termination is surfaced as failure, and execution failures use MCP error status. Local unit tests cover timeout/cancellation descendants and an MCP integration test covers a timed-out descendant. Detached descendants may escape; this is not a sandbox or general proxy process controller. Cross-platform hosted execution remains outstanding. |
| Single-turn captured replay | Implemented, narrowly | Only complete, hash-valid schema-v1 non-streaming chat-completion captures are eligible. Missing, malformed, unsupported, tampered, or streaming traces fail explicitly. Repeated retrieval after daemon restart is stable and makes zero upstream calls; playback returns stored inputs/outputs and does not re-run an agent or prove multi-turn determinism. |
| 240-hour replay | Not implemented/verified | No long-duration or multi-turn deterministic execution replay evidence. |
| Zero-cost fork/resume | Not verified | Cached turns do not establish zero cost or complete forked execution. |
| Secret filtering | Partial | Common credential patterns are denied in managed actions; field-aware and text-pattern redaction covers known secret fields in traces, approvals, and execution summaries. This remains heuristic and does not cover every secret format or prompt path. |
| Virtual filesystem | Isolated module | Not wired into agent I/O; path containment is checked, but it is not a sandbox. |
| Cryptographic attestation / PR evidence | Not suitable for trust claims | Current helper does not establish trusted identity or prove that changes were in scope. |
| 1,000-developer evaluation | Withdrawn | Former report was generated from synthetic random scores and fabricated feedback. |
| Production release gate | Defined locally; BLOCKED | The release workflow requires a clean platform/runtime matrix, installed-package smoke, exact-commit evidence, a real-agent run, independent security review, and observed pilot. Current local macOS checks do not satisfy remote CI or Linux/Windows validation. Prior bounded Codex CLI evidence is for an uncommitted candidate, not release-bound evidence. A pilot form exists but no participant results are recorded. The package smoke is wired into workflows but has not run on hosted CI. The owner selected MIT and package metadata plus `LICENSE` are present; license terms have not been independently reviewed, and the other release gates remain unmet. See [release gate](RELEASE_GATE.md) for evidence requirements. |

Do not upgrade these statuses based on unit tests alone. Any move to broader “enforced” or “production-ready” requires end-to-end tests through actual supported agent clients, adversarial path/argument coverage, cross-platform CI results, and an independent security review.
